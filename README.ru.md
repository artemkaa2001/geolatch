# GeoLatch

Лёгкая утилита географической фильтрации входящего трафика Linux: отдельные списки стран для разных IP сервера, автоматическое обновление баз, двуязычный терминальный интерфейс и безопасный откат.

Пакеты фильтрует ядро Linux через nftables. Python только управляет конфигурацией, загрузкой CIDR и интерфейсом. Веб-панель, платные API, регистрация, сервер базы данных и постоянно работающий обработчик пакетов не нужны.

Разработчик: [@artemkaa_2001](https://t.me/artemkaa_2001). Лицензия приложения: [MIT](LICENSE).

## Требования и установка

Автоматический установщик рассчитан на Ubuntu 22.04/24.04/26.04 LTS и актуальный Debian, архитектуры x86_64 и ARM64, Python 3.10+, nftables и systemd. Это целевые платформы совместимости; фактические проверки перечислены в [отчёте](docs/verification.md). Нужны административные права и исходящий HTTPS к выбранному источнику GeoIP.

```sh
git clone https://github.com/artemkaa2001/geolatch.git && cd geolatch && sudo ./install.sh
```

Установщик проверяет систему, устанавливает зависимости через пакетный менеджер, создаёт изолированное Python-окружение, регистрирует глобальную команду и systemd units, затем автоматически открывает полноэкранный мастер. До обзора и подтверждения политики правила firewall не меняются. Первый полноценный экран предлагает English / Русский; язык системы влияет только на первоначальное выделение.

При повторной установке доступны «Открыть», «Обновить», «Восстановить», «Отмена». Конфигурация `/etc/geolatch/config.yaml`, локальные базы и действующие правила сохраняются. Для установки без терминала явно укажите `sudo ./install.sh --no-setup`; при существующей установке нужен также `--upgrade` или `--repair`. Этот режим автоматизации сам не настраивает фильтрацию.

Если старая версия оставила незавершённое применение, скачайте актуальные исходники и выполните `sudo bash install.sh --repair`. Восстановление сохранит выбранные настройки в отдельный черновик, откатит неподтверждённые правила исправленной версией и откроет черновик для повторной проверки и применения. Подробнее: [восстановление](docs/troubleshooting.md).

## Мастер и повседневное управление

Мастер показывает реальные сетевые интерфейсы и IPv4/IPv6, позволяет выбрать destination IP, заблокированные страны, источник GeoIP и доверенные административные CIDR. Docker bridges, loopback и туннели требуют особого внимания. Выбирайте адрес назначения, который сервер видит **до DNAT**; при внешнем NAT провайдера это может быть частный адрес сервера.

Клавиши: ↑/↓ — перемещение, Space — отметка checkbox, Enter — выбор, Tab — смена фокуса, Esc — назад, Q — выход там, где применимо, Ctrl+C — корректное завершение. Страны можно искать по локализованному названию и ISO-коду. До просмотра и применения изменения остаются черновиком. Язык переключается в «Настройки → Язык» сразу, без перезапуска, и сохраняется для следующих запусков.

Для открытия главного меню достаточно:

```sh
geolatch
```

Для изменения firewall нужны права root: привилегированные операции используют `sudo`, без setuid Python и постоянного управляющего root-демона. Чтение фактических nftables rules также может требовать повышенных прав; в таком случае обычный пользователь увидит, что состояние недоступно для проверки.

## Несколько политик

Например, первая политика блокирует `IR` и `PK` на `203.0.113.10`, вторая — `CN` на `203.0.113.20`, а третий адрес не включён в политики. Мастер позволяет добавить следующую политику без повторения всей начальной настройки. Для одного destination списки стран разных политик объединяются. Пустой список не отменяет блокировку другой политики.

Эквивалент YAML приведён в [examples/config.yaml](examples/config.yaml). Все IP в этом примере документационные: перед использованием замените их, интерфейс и административный CIDR своими реальными значениями. При работе через TUI ручное редактирование YAML не требуется.

`destinations: all` означает подходящие публичные локальные адреса на выбранных интерфейсах. Это не глобальный запрет forwarded-трафика. Адреса определяются заново при apply, update и восстановлении после загрузки. Постоянного наблюдения за изменением адресов нет: после изменения сети повторите применение. Подробнее: [конфигурация](docs/configuration.md).

## CLI и защита SSH

```sh
geolatch --help
geolatch --lang ru status
geolatch addresses --json
geolatch countries
geolatch plan
sudo geolatch apply
sudo geolatch confirm TOKEN
sudo geolatch update --dry-run
sudo geolatch update
sudo geolatch rollback
sudo geolatch disable --yes
sudo geolatch enable
geolatch check-ip 1.2.3.4 --destination 203.0.113.10
sudo geolatch doctor
geolatch logs
geolatch version
```

`setup` открывает мастер и требует терминал. `plan` показывает изменения без их применения. Глобальные параметры `--config FILE`, `--state-dir DIR`, `--cache-dir DIR`, `--lang en|ru` и `--json` указываются перед подкомандой; диагностические команды также принимают `--json`. JSON-ключи не зависят от языка. `--lang` меняет язык только текущего вызова. `check-ip` рассчитывает соответствие политике GeoLatch по локальным данным и не проверяет сквозную сетевую связность.

Ручной apply запускает независимый watchdog отката и выдаёт токен подтверждения. Подтвердите применение за 90 секунд, иначе восстановится предыдущее подтверждённое состояние. В TUI для этого есть отдельный экран. `apply --timeout 180` увеличивает окно подтверждения в поддерживаемых пределах. При первом запуске держите отдельную SSH-сессию и консоль провайдера. Allowlist исключает источник только из ограничений GeoLatch и не отменяет чужие правила. При использовании bastion/proxy адрес в `SSH_CONNECTION` может не совпадать с вашим публичным административным IP.

Для осознанной автоматизации предусмотрено `sudo geolatch apply --yes --confirm`: правило фиксируется без дополнительного подтверждения доступности. Это явно отключает интерактивное окно безопасности для данной операции. `update --force` не отключает проверку CIDR и защиту от аномалий. Аварийное восстановление описано в [безопасности](docs/security.md).

## Обновления и перезагрузка

После подтверждения включается systemd timer с ежедневным расписанием, `Persistent=true` и случайной задержкой. Кратковременный сервис получает все необходимые страны и IP-family, проверяет формат, контрольные суммы и аномалии количества сетей и покрытия адресов. Только после полной проверки выполняется атомарная транзакция nftables. Ошибка источника не очищает действующие sets. При неизменившихся данных лишняя перезагрузка правил не нужна.

Расписание и журнал: `systemctl list-timers geolatch-update.timer`, `journalctl -u geolatch-update.service`. Сервис `geolatch-restore.service` восстанавливает подтверждённую конфигурацию из локальных данных без скачивания из интернета, после nftables/UFW и network-online, до Docker. Для `all` нужен корректный wait-online вашего сетевого менеджера. Последующая перезагрузка правил чужого firewall может изменить состояние: GeoLatch не управляет сторонними сервисами. Проверка offline restore и реальная перезагрузка машины — разные проверки.

## Совместимость и ограничения

GeoLatch управляет только `table inet geolatch`. Цепочка prerouting priority `-150` работает после conntrack и до обычного DNAT priority `-100`, чтобы учитывать опубликованные Docker-порты. Правила ограничены выбранными входящими интерфейсами и destination IP. Allowlist и сохранённые established/related возвращают обработку из цепочки GeoLatch; глобального ACCEPT нет. IPv6 Neighbor Discovery сохраняется.

Совместимость с UFW, Docker, iptables-nft, Nginx, HAProxy, Xray и VPN зависит от фактических hooks, интерфейсов, NAT и conntrack. При DNAT вне сервера destination уже другой. Более ранние нестандартные NAT hooks, notrack, flowtable/аппаратный offload, прокси и туннели требуют отдельной проверки. Не выбирайте туннель или bridge без понимания его трафика. Подробнее: [firewall](docs/firewall.md).

GeoIP приблизительно классифицирует IP и не доказывает физическую страну пользователя. VPN, прокси, роуминг и ошибки баз влияют на результат. Географическая фильтрация не заменяет аутентификацию и защиту сервисов.

## Источники и лицензии

Основной источник `ipverse-geo`: [ipverse/geo-ip-blocks](https://github.com/ipverse/geo-ip-blocks). Компактный `ipverse-rir`: [ipverse/country-ip-blocks](https://github.com/ipverse/country-ip-blocks), на основе регистрационных данных RIR. Покрытие и точность могут различаться. При сбое GeoLatch не переключает provider автоматически. HTTPS-загрузки ограничены по времени, числу попыток и размеру. SHA-256 проверяет целостность локального cache, но не является независимым доказательством подлинности upstream.

MIT-лицензия приложения не распространяется автоматически на GeoIP-данные. Актуальные проверенные условия и ссылки находятся в [документации источников](docs/sources.md). Сами базы CIDR в репозиторий не включены. Названия стран из Debian `iso-codes` распространяются отдельно под LGPL-2.1-or-later с [уведомлением](geolatch/locales/COUNTRIES-LICENSE.txt).

## Диагностика и удаление

Используйте `sudo geolatch doctor`, `geolatch logs` и systemd journal. Недоступные проверки и ошибки нужно устранить до вывода о работоспособности фильтрации. [Диагностика](docs/troubleshooting.md), [архитектура](docs/architecture.md), [локализация](docs/localization.md) и [результаты проверок](docs/verification.md) описывают реализацию подробнее. Unit tests и mocks сами по себе не подтверждают работу netfilter.

```sh
sudo ./uninstall.sh
# Если исходный репозиторий недоступен:
sudo /opt/geolatch/current/uninstall.sh
```

Удаление останавливает задания GeoLatch, убирает только собственные rules и программу, затем сохраняет или удаляет данные по вашему выбору. `--yes` пропускает подтверждение удаления и сохраняет данные; `--purge` явно удаляет также конфигурацию, снимки, cache и журналы. Системный nftables, UFW, чужие таблицы и маршруты не изменяются.
